# ONNX Offline Inference Scenario Solution

## Information Collection

This document uses the Atlas 200I A2 acceleration module as an example to analyze the following information that you usually need to collect in an Atlas 200I A2 inference scenario.

**Profiling Information Collection**

For details about how to collect Profiling data, see the [msprof Model Tuning Tool](https://atomgit.com/Ascend/msprof/blob/master/docs/en/quick_start/msprof_quick_start.md).

1. Log in to the running environment and go to the directory where the msprof tool is located, `/var`.

2. Run the following command to collect performance data. `application` is the user program.

   ```shell
   msprof --output={path} {application}
   ```

   Command example:

   ```shell
   msprof --output=${HOME}/profiling_output ${HOME}/HIAI_PROJECTS/MyAppname/out/main
   ```

3. After the command is executed, a `PROF_XXX` directory is generated in the directory specified by `--output`. The directory structure is as follows.

   ```text
   ├── device_{id}
   │├──data
   │└──...
   └──host
   │├──data
   │└──...
   ```

4. Upload the `PROF_XXX` directory to the development environment where the toolkit package is installed, and run the following command to parse the data.

   ```shell
   msprof --export=on --output=<dir>
   ```

   New data files are added in the `PROF_XXX` directory. The directory structure is as follows:

   ```text
   ├── device_{id}
   │├──data
   ├──host
   │├──data
   │└──...
   └──mindstudio_profiler_output
   │├──xx_*.csv
   │├──xx_*.json
   │└──...
   ...
   ```

**Log Collection for Converting ONNX to OM Through ATC**

Set the log level for converting the ONNX file, and redirect the log output to a file. To analyze this issue, perform the following steps:

1. Configure the ATC runtime environment variables.

   ```cfg
   export ASCEND_SLOG_PRINT_TO_STDOUT=1
   export ASCEND_GLOBAL_LOG_LEVEL=0
   ```

2. Add `--log=debug` to the ATC command to collect conversion logs.

   Command example:

   ```shell
   atc --model=$modelPath/$onnxfile \
   --log=debug \
   --framework=5  \
   --input_shape="x:$batchsize,3,$height,$width" \
   --input_fp16_nodes="x" \
   --output_type=FP16 \
   --op_select_implmode=high_precision \
   --output=$outputPath/$outname  \
   --soc_version=Ascendxxxyy \  # xxxyy is the actual chip type that you use
   ```

3. Run ATC again, redirect the output information to a log text file, and obtain that file together with the `fusion_result.jsonl` file generated by the ATC run for subsequent performance analysis.

**Collecting Inference Logs**

Run the OM file to perform inference and collect the logs output by inference. The collection steps are as follows:

1. Configure the runtime environment variables for the OM model.

   ```cfg
   export ASCEND_SLOG_PRINT_TO_STDOUT=1
   export ASCEND_GLOBAL_LOG_LEVEL=1
   ```

2. Then run the OM file and redirect the output information to a log text file.

**Providing the ONNX and OM Files from Before and After ATC Conversion**

ONNX is currently one of the most mainstream model formats in the industry and is widely used for model exchange and deployment. Offline inference requires converting the ONNX file to an OM file for inference.

Collect both the ONNX file exported from the model run in the training environment and the OM file generated by conversion for subsequent analysis.

## Optimization Methods

### Model Compression and Quantization

Quantization can compress a model and reduce the amount of computation.

> [!NOTE]
>
> - Ascend supports quantization only for Cube operators (MatMul and Conv).
> - Quantization inserts some data conversion operators, which may cause performance deterioration. If you need quantization, you are advised to use methods such as AOE to optimize the model after quantization and compare the performance before and after quantization. For the AOE method, see [ONNX Model Tuning](#onnx-model-tuning).

Quantization methods include the following:

- Quantization through ATC: use the `--compression_optimize_conf` parameter during ATC conversion to directly obtain the quantized OM file. For details about the usage, see the [ATC Offline Model Compilation Tool User Guide](https://www.hiascend.com/document/detail/en/CANNCommunityEdition/latest/devaids/atctool/docs/en/user_guides/atc_tools/overview/learning_guide.md) and its [Parameters](https://www.hiascend.com/document/detail/en/CANNCommunityEdition/latest/devaids/atctool/docs/en/user_guides/atc_tools/CLI_options/general_restrictions.md).
- `AMCT_ONNX`: quantize the ONNX model. You need to download and install "AMCT (ONNX)", which is equivalent to the ONNX version of ATC parameter quantization. You can obtain the AMCT tool from the CANN software download link. AMCT supports joint quantization and may provide additional performance improvement on the ResNet structure.
- msModelSlim tool: quantize the ONNX model. This tool is provided with the CANN package and does not require installation. It supports quantization of ONNX models larger than 2 GB. For usage guidance, see the [msModelSlim tool](https://atomgit.com/Ascend/msmodelslim/blob/master/docs/en/quick_start/quantization_quick_start.md).

### ONNX Model Tuning

#### Simplifying the ONNX File

ONNX Simplifier is an open-source tool that simplifies ONNX models. It infers the entire computation graph and replaces redundant operators with constant outputs (also called constant folding).

Run the following commands to use the ONNX Simplifier tool.

```shell
pip install onnx-simplifier
onnxsim -h  # View the parameter description
onnxsim  --overwrite-input-shape="1,3,224,24" efficient.onnx efficient_sim.onnx
```

As shown in [Figure 1](#ZH-CN_TOPIC_0000002535807047__fig1360715412575), after you run onnxsim on the exported ONNX file, you can see that some operations in the ONNX model are reduced.

#### AOE Tuning

For products in EP mode, you can perform AOE tuning directly in the environment where the OM model runs. The reference command is as follows:

```shell
aoe --framework 5 --model ./model.onnx --output model --job_type 2 --ip xx.xx.xx.xx --aicore_num=1
```

For detailed parameter explanations and usage, see the [AOE Tuning Tool User Guide](https://www.hiascend.com/document/detail/en/CANNCommunityEdition/latest/devaids/aoe/auxiliarydevtool_aoe_0001.html).

#### NCS Tuning

Some products run in RC mode and generally have a small memory capacity. As a result, the model cannot be tuned through local AOE, and another tuning method, NCS tuning, is required.

##### Configuring Key Certificates

First, ensure that the host machine and the device machine are on the same primary network segment and can ping each other.

1. Upload a shell script to the host machine. The script is as follows:

   ```shell
   DEVICE_IP=10.x.x.196   # Your device ip
   HOST_IP=10.x.x.66 # Your host IP
   PASS_PHRASE=Ncx12345 # Your pass phrase
   KEY_LEN=3072 # [3072,4096]
   VALID_DAYS=365 # The cert will expire after the valid days
   COUNTRY=CN # Your country name abbr.(2 letter code)
   STATE=Zhejiang # Your province name
   LOCATION=Hangzhou # Your city name
   ORGANIZATION=ABC # Your company name
   ORGANIZATION_UNIT=DEF # Your section name
   COMMON_NAME_ROOT=www.aoe.com # Your domain name
   ENCRYPT_MODE=aes256 # [aes256,aes128]

   ########## Modify the content preceding this separator line based on your actual situation. Modifying the following content is not advised. ##########

   # Generate conf
   rm -rf host-ext.cnf device-ext.cnf
   echo "[ext]" >> host-ext.cnf
   echo "subjectAltName=IP:${HOST_IP}" >> host-ext.cnf
   echo "[ext]" >> device-ext.cnf
   echo "subjectAltName=IP:${DEVICE_IP}" >> device-ext.cnf

   # Generate root cert
   openssl req -x509 -newkey rsa:${KEY_LEN} -days ${VALID_DAYS} \
   -nodes -keyout ca-key.pem -out ca-cert.pem \
   -subj "/C=${COUNTRY}/ST=${STATE}/L=${LOCATION}/O=${ORGANIZATION}/OU=${ORGANIZATION_UNIT}/CN=${COMMON_NAME_ROOT}" \
   -addext keyUsage=keyCertSign

   # Generate device cert request
   openssl req -newkey rsa:${KEY_LEN} -nodes -keyout device-key.pem -out device-cert.csr -subj "/C=${COUNTRY}/ST=${STATE}/L=${LOCATION}/O=${ORGANIZATION}/OU=${ORGANIZATION_UNIT}/CN=NCS"

   # Generate device cert
   openssl x509 -req -in device-cert.csr -days ${VALID_DAYS} -CA ca-cert.pem -CAkeyca-key.pem -CAcreateserial -out device-cert.pem -extensions ext -extfile device-ext.cnf

   # Generate host cert request
   opensslreq-newkeyrsa:${KEY_LEN}-nodes-keyouthost-key.pem-outhost-cert.csr-subj"/C=${COUNTRY}/ST=${STATE}/L=${LOCATION}/O=${ORGANIZATION}/OU=${ORGANIZATION_UNIT}/CN=NCA"

   # Generate host cert
   openssl x509 -req -in host-cert.csr -days ${VALID_DAYS} -CA ca-cert.pem -CAkey ca-key.pem -CAcreateserial -out host-cert.pem -extension ext -extfile host-ext.cnf

   # encrytprivatekey
   openssl rsa -in host-key.pem -passout pass:${PASS_PHRASE} -${ENCRYPT_MODE} -out host-key.pem
   openssl rsa -in device-key.pem -passout pass:${PASS_PHRASE} -${ENCRYPT_MODE} -out device-key.pem
   ```

### Graph Modification Optimization

If automatic optimization cannot meet the target, or you have identified redundant computation in the model, or you need to adjust the data type so that an operator switches from running on the AI CPU to running on the AI Core, you can optimize performance through graph modification.

The following example adds a Cast operation before the GlobalAveragePool operation. The graph modification script is as follows:

```python
import onnx
from onnx import helper, TensorProto
from onnx import shape_inference
model_path = "D:\\035-Code\\om_test\\resnet50.onnx"
model = onnx.load(model_path)
def create_cast_node(input_name, output_name, to_type):
    return helper.make_node(
        'Cast',
        inputs=[input_name],
        outputs=[output_name],
        to=to_type
    )
for i, node in enumerate(model.graph.node):
    if node.op_type == 'GlobalAveragePool':
        # Get the input of the GlobalAveragePool node
        input_name = node.input[0]
        # Generate the output name of the new Cast node
        cast_output_name = f"{input_name}_cast"
        # Create the Cast node
        cast_node = create_cast_node(input_name, cast_output_name, TensorProto.FLOAT)
        # Update the input of the GlobalAveragePool node
        node.input[0] = cast_output_name
        # Insert the Cast node into the computation graph
        model.graph.node.insert(i, cast_node)
        break  # Process only the first GlobalAveragePool node found
output_model_path = "D:\\035-Code\\om_test\\resnet50_new.onnx"  # Replace with the model path where you want to save
onnx.save(model, output_model_path)
```
